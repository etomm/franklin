# 0003 — WiFi Insight from the vendor sources (vis_gui)

**Status:** blocked by 0002 (variant E) · **Fixes:** alignment #4 ·
**Depends on:** an httpd built with `vis_gui`

## Why

Today Franklin substitutes the MIT addon for gnuton's stub page. The real
implementation exists, split in two halves:

| half | where | state |
|---|---|---|
| pages | XT9 GPL: `.../impl87/main/components/apps/visualization/www/` (`visindex.asp`, `metrics.asp`, `channelcapacity.asp`, `configure.asp`, `channels.asp`, `zerowaitdfs.asp` + js/css) | present |
| backend | XT9 GPL: `httpd/vis_gui.c` → handlers `json.cgi*`, `visdata.db*` | source present, **compiled out of both httpd binaries** (`strings httpd \| grep -c json.cgi` → 0) |
| assets | ~15 JS/CSS (`jquery.flot*`, `curvedLines.js`, `jquery.tablesorter.min.js`, `highlightseries.js`, logo/background images) | **absent from the GPL and both firmwares** |
| data | `visdata.db` (produced by `vis_do_visdbdwnld_cgi` / the visualization pipeline) | absent |

So the feature is not "missing"; it is **switched off at build time** and its
static assets are not published.

## Steps

1. **Confirm the build switch**: in `httpd/Makefile` and `vis_gui.c`, find the
   guard (`RTCONFIG_WIFI_RADAR` / similar) and the `OBJS` entry; record what the
   XT9 model config sets.
2. **Collect the assets**: locate them in a model whose firmware ships WiFi
   Insight (AI-router class) or in Broadcom's SDK package used by that build.
   Inventory exactly the files the pages request (the list is in
   `docs/experiments/httpd-variants.md` and reproducible with
   `grep -rhoE '(src|href)="[^"]+"'`).
3. **Build httpd with `vis_gui`** (this is variant E of plan 0002) and verify the
   handlers appear: `strings httpd | grep json.cgi` → non-empty.
4. **Ship the vendor pages** as a delta (no edits) and advertise the capability
   token the menu expects, through `ui-capabilities` (never patch `menuTree.js`
   for this).
5. **Data pipeline**: check whether `visdata.db` is generated by an rc action
   (`vis_do_visdbdwnld_cgi` suggests a download endpoint) or must be produced by
   a companion job; if a companion is needed, implement it as a `franklin-rc`
   action, not inside httpd.
6. **Retire the MIT addon** (`features/wifi-insight/`) once the vendor pages pass,
   or keep it as an opt-in fallback with this plan's outcome documented.

## Acceptance

- `/visindex.asp`, `/metrics.asp`, `/channelcapacity.asp`, `/configure.asp`
  return vendor pages (byte sizes match the GPL copies).
- `/json.cgi?Req=…` answers with JSON; pages draw channels/metrics.
- No MIT addon files in `/www`, no `menuTree.js` patch for WiFi Insight.
- `strings /opt/bin/gnuton-httpd | grep json.cgi` → non-empty.

## Rollback

Keep the MIT addon feature available (`--add wifi-insight`) until acceptance
passes; uninstalling it is the `ui-capabilities` token plus the page install.

## Files

`features/wifi-insight/*` (retire), `features/web-ui/build.sh` (pages delta once
built from a `vis_gui` httpd), `features/ui-capabilities` (token), plan 0002's
build outputs.
